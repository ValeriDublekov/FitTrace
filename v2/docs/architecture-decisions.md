# Архитектурни решения (Architecture Decision Records - ADR)

Този документ описва ключовите архитектурни решения, взети при дизайна на версия 2 (v2) на FitTrace, причините за тях и търсените резултати.

---

## ADR-001: Изолирана паралелна структура (`v2/`) без прекъсване на v1
- **Статус:** Прието
- **Контекст:** Текущото Firebase PWA приложение се използва активно в залата и не трябва да се чупи или подлага на рискове по време на разработка на бекенда.
- **Решение:** Цялата нова архитектура (бекенд, база данни, индексни документи и нов клиентски слой) се обособява в отделна директория `v2/`. Коренът на репозиторито и текущият v1 app остават 100% непокътнати.
- **Свързани файлове:**
  - План за миграция: [implementation_plan.md](../../.aistudio/artifacts/brain/6be0d495-1c19-4e4f-b7e3-6dfef8b54845/implementation_plan.md)
  - Docker Compose: [docker-compose.yml](../docker-compose.yml)

## ADR-002: Избор на релационна база данни (PostgreSQL 16)
- **Статус:** Прието
- **Контекст:** NoSQL базата (Firestore) създава сериозни затруднения при агрегации, изчисляване на прогрес (1RM, тонаж по мускулни групи), денормализация и схематични промени.
- **Решение:** Миграция към PostgreSQL 16 с Entity Framework Core.
- **Последици:**
  - Стриктна релационна цялост с чужди ключове (`Users` -> `Workouts` -> `WorkoutExercises` -> `ExerciseSets`).
  - Миграции с код чрез EF Core (`dotnet ef migrations add`).
  - Възможност за бързи агрегатни SQL заявки.
- **Свързани файлове:**
  - Индекс на базата данни: [database-index.md](./database-index.md)
  - EF Core контекст: [AppDbContext.cs](../backend/src/FitTrace.Data/AppDbContext.cs)

## ADR-003: Достъп до домашния сървър чрез Cloudflare Tunnel
- **Статус:** Прието
- **Контекст:** Домашният сървър трябва да бъде достъпен от мобилния телефон на трениращия в залата, без статичен IP и без отваряне на портове в домашния рутер.
- **Решение:** Интегриране на лек `cloudflared` контейнер в Docker Compose, който изгражда криптиран тунел към Cloudflare Zero Trust мрежата.
- **Последици:** Автоматичен валиден SSL/TLS сертификат, DDoS защита и сигурна връзка без port forwarding.
- **Свързани файлове:**
  - Конфигурация: [docker-compose.yml](../docker-compose.yml)

## ADR-004: Модулна .NET 9 архитектура според SOLID, DRY и KISS
- **Статус:** Прието
- **Контекст:** Кодът на бекенда трябва да бъде лесен за поддръжка, четим и лесно тестваем.
- **Решение:** Разделяне на проекта на 3 слоя:
  1. `FitTrace.Core`: Entities, DTOs, интерфейси и бизнес изчисления (1RM, обем).
  2. `FitTrace.Data`: EF Core конфигурации, контекст и базисни репозитори операции.
  3. `FitTrace.Api`: Леки REST контролери и DI конфигурация.
- **Последици:** Изолирана бизнес логика, която се тества светкавично с автоматизирани xUnit тестове без външни зависимости.
- **Свързани файлове:**
  - Индекс на API: [api-index.md](./api-index.md)
  - Тестов проект: [FitTrace.Tests](../backend/tests/FitTrace.Tests/)

## ADR-005: Тестова стратегия за базовата функционалност
- **Статус:** Прието
- **Контекст:** Потребителят изисква автоматизирани тестове за базова функционалност (изчисления, валидации, запис на сесии), без прекомерно усложняване с тестване на ауторизация.
- **Решение:** xUnit тестове с FluentAssertions и EF Core InMemory / SQLite за тестване на:
  1. Формули за 1RM и пресмятане на тренировъчен обем.
  2. Валидация и нормализиране на серии при запис на тренировка.
  3. Разграничение между глобални и персонализирани (custom) упражнения.
- **Свързани файлове:**
  - [WorkoutCalculationsTests.cs](../backend/tests/FitTrace.Tests/WorkoutCalculationsTests.cs)
  - [WorkoutServiceTests.cs](../backend/tests/FitTrace.Tests/WorkoutServiceTests.cs)
